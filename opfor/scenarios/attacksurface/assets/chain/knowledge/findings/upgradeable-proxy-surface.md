# Upgradeable Proxy Surface

An upgrade or initialize path that can change the code sitting behind the funds, an `upgradeTo`, an
`_authorizeUpgrade`, or an initializer that a race or a missing guard leaves open. It matters
because the audited code is not the code that will run if the implementation can be swapped, and an
uninitialized proxy is a known takeover shape.

How it moves the priority. On a fund-holding contract it is a dependency-class signal, it raises a
reachable-fund-path target and, for an uninitialized-proxy shape, is itself worth a look regardless
of the fund path, since seizing the implementation seizes the funds.

Signals that mark it. `upgradeable_proxy` from the detection data.
